2026-08-03 разобран соседний проект юзера `C:\Users\user\4.6 billion years of simphony` — конвейер LLM-перевода веб-новеллы (~4900 глав, 16 параллельных слотов autorun, глоссарное хозяйство, QC с калибровкой, публикация на RanobeLib). Структурно — старший брат нашего i18n-конвейера ([[i18n-data-translations]], [[i18n-ui-quality]]). Воркфлоу из 7 агентов свёл опыт в 8 практик; юзер велел внедрить №1, 2, 5, 8.

**ВНЕДРЕНО 2026-08-03 (решение юзера):**
1. **Гейт на скаффолдинг + карантин** — `scripts/i18n_tool.py::find_scaffolding` (одна реализация на три точки): merge/merge-ui отправляют фрагмент с обвязкой целиком в `scratch/i18n_rejected/` (exit 1), правило `test_no_agent_scaffolding_residue` в обоих гейтах, юнит-тесты `tests/test_i18n_scaffolding.py`. Легальны BBCode/плейсхолдеры/`g.<name>` — паттерны скоуплены на LLM-обёртки.
2. **Контракт субагентов** — 6 из 8 уже соответствовали (минимум tools + парсимая строка). Дочинено: i18n-translate обязан репортить «новые термины» (вход для канонизации до следующей волны), `forbidden` теперь реально вкладывается в батчи (контракт это обещал, код не делал), scout получил парсимый заголовок.
5. **Двусторонний глоссарный гейт** — `tests/test_i18n_terminology.py`: коллизии глоссария (два термина → одно слово), коллизии имён внутри секции, разные переводы одного base-имени. Исключения — данными в `collisions_ok` глоссария (слово → причина; первая запись: намеренная омонимия tier/level → «уровень»/«рівень»), гейт требует причину у каждого.
8. **Идемпотентная публикация** — `publish_content.py`: план по умолчанию, запись только по `--publish`; `check_remote_sync` перед чеканкой ревизий (live впереди чекаута = отказ); `--check-live` сверяет Pages с docs/content побайтово (sha256); `_dump` атомарен (mkstemp+os.replace).

**Открытое, найдено при внедрении:** `docs/content/packs/*.v1.json` перегенерированы в рабочем дереве **без бампа ревизии** — если запушить как есть, клиенты с кэшем v1 обновления не увидят (кэш по номеру ревизии). Перед публикацией паков собрать их через `publish_content.py --packs ... --publish` (сам чеканит v2), а не пушить правленные v1.

**ВНЕДРЕНО 2026-08-03, вторая волна (№3/4/6/7):**
3. **Prewave** — `i18n_tool.py prewave <ref>`: слова, повторяющиеся в новых с `<ref>` ключах/записях, но отсутствующие в старом корпусе и глоссарии (фильтр стоп-слов бесплатно — частое старое слово не кандидат). Exit 1, пока судья не разложит кандидатов: термин → колонки глоссария, не термин → `prewave_ignore` с причиной (гейт требует причину). Порядок волны вписан в docstring инструмента: prewave ДО раздачи батчей.
4. **Релизный чек** — `scripts/release_check.py`: весь pytest + целостность docs/content против манифеста (файлы существуют/парсятся, revision в паке = revision в манифесте, sha256 шрифтов, orphan-файлы) + orphan-ключи языков против en + гигиена незакоммиченных release-inputs; `--live` подключает `check_live` из publish_content. FAIL/WARN раздельно, exit 1 только на FAIL. Разделение труда с pytest-гейтами и buildcheck задокументировано в docstring и проверено ревьюером.
6. **Эскалация + леджер** — карантин нумеруется (`.2`, `.3`, …), стопка копий = счётчик ретраев, пересчитанный с диска; на 3-м карантине печатается ESCALATE (четвёртый запуск того же промпта ничего не инспектирует). Все исходы merge/quarantine — в `scratch/i18n_ledger.jsonl`; `status`/`status-ui` аннотируют батчи карантинами. Токен-леджер не переносился: у i18n_tool нет доступа к usage агентов (это видит только оркестрирующая сессия).
7. **Слепой QA + калибровка** — `qa-sample <lang>`: выборка по селекторам (machine / glossary-term / long-prose) + ~25% контроля из ранее принятых ключей; task-файл без причин отбора, причины — в `.meta.json`, который агенту не дают. `qa-report`: вердикты × селекторы → `scripts/i18n_calibration.json` (точность каждого селектора; правило становится блокирующим только по измеренной точности), пробитый контроль подсвечивается. i18n-qa.md: режим выборки + правило «не угадывай причину отбора».

**Их грабли — не повторять:** корень репо как свалка логов прогонов (~150 файлов); opt-in гейты (забытый `--prewave` = 13 разъехавшихся терминов — гейты default-on); вера отчёту агента без проверки артефакта на диске («успех» без файла уронил прогон на 3464 главы); паттерн-матчинг числовых полей при классификации ошибок (duration=74293 «содержал 429» — выбросили готовую главу); подсказка ожидаемого вердикта контрольной группе в промпте.
