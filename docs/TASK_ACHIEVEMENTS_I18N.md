# Задача: достижения (и прочие данные) показываются по-английски при русском UI

## Симптом
В игре с русским интерфейсом названия/описания достижений отображаются по-английски
(«First Blood» вместо «Первая кровь»). Выглядит как «пропущенные переводы», но это НЕ так.

## Проверенные факты (не перепроверять, уже сделано 2026-07-25)
- Переводы данных ПОЛНЫЕ: `data/languages/data_{ru,uk,de,es,fr,it,pt,pl}.json`, секция
  `achievements` — 50/50 записей с `name`+`desc` в каждом языке. Дозаполнять нечего.
- Механизм наложения работает: `data_loader.apply_translations(lang)`
  ([game/data_loader/translationmixin.py](../game/data_loader/translationmixin.py), строка 49 кроет achievements)
  → `GameEngine._wire_data()` пересобирает рантайм-список
  ([game/engine/wiringmixin.py](../game/engine/wiringmixin.py):68 → `build_achievements_from_json`).
- Оба пути смены языка корректны и полны: первый запуск
  ([game/app/applocalemixin.py](../game/app/applocalemixin.py):110 `_finish_first_launch`) и настройки
  ([game/screens/more/helpmixin.py](../game/screens/more/helpmixin.py):81 `_set_language`).
- UI-список строится через RecycleView (`achievements_rv` в [kv/lore_screen.kv](../kv/lore_screen.kv):99),
  данные берутся из переведённого `ACHIEVEMENTS` при каждом входе — этот слой чист.

## Корневая причина (баг №1, главный)
[game/engine/persistencereadmixin.py](../game/engine/persistencereadmixin.py):126–133:

```python
saved_lang = data.get("language")
if saved_lang:
    set_language(saved_lang)
    data_loader.apply_translations(saved_lang)
    self._wire_data()
```

Наложение переводов данных выполняется ТОЛЬКО если в сейве есть ключ `language`.
Если ключа нет (сейв от старой версии до появления снапшота языка, облачный сейв старого
формата, руками отредактированный) — UI-строки берут дефолт `ru`
(`_current_lang = "ru"` в [game/localization.py](../game/localization.py):16), а данные
(достижения, экспедиции, классы, травмы, лор, зачарования) остаются английскими,
потому что `apply_translations` не вызывается вовсе.

Ключ пишется в [game/engine/persistencesnapshotmixin.py](../game/engine/persistencesnapshotmixin.py):74 —
свежие сейвы его содержат, старые — нет.

### Подтверждённое воспроизведение (десктоп)
```python
import json, tempfile, os
from game.engine import GameEngine
import game.achievements as A
fd, path = tempfile.mkstemp(suffix=".json"); os.close(fd)
json.dump({"gold": 100}, open(path, "w"))          # сейв БЕЗ ключа "language"
e = GameEngine(save_path=path); e.load()
print(A.ACHIEVEMENTS[0]["name"])                    # -> "First Blood"  (БАГ)
# с {"gold": 100, "language": "ru"} -> "Первая кровь" (ок)
```

### Требуемый фикс
В `load()` применять переводы данных для ЭФФЕКТИВНОГО языка всегда, а не только при
наличии ключа: `lang = data.get("language") or get_language()`; при `lang != "en"` —
`set_language(lang)` (если был ключ) + `data_loader.apply_translations(lang)` +
`self._wire_data()`. Порядок относительно остального `load()` не менять (блок уже стоит
до чтения inventory — так и оставить). Сейв сам «мигрирует» при следующем `save()`
(снапшот пишет текущий язык) — отдельная миграция не нужна.

## Баг №2 (латентный, починить заодно)
[game/ui_helpers/_lore.py](../game/ui_helpers/_lore.py):167–180, легаси-ветка GridLayout:
кэш карточек инвалидируется только по хэшу unlocked-флагов
(`unlock_hash = tuple(ach.get("unlocked", ...))`) — смена языка кэш не сбрасывает, карточки
остаются на старом языке. Сейчас ветка мертва (kv использует RecycleView), но это ловушка.
Фикс: включить текущий язык в ключ кэша (`(get_language(), unlock_hash)`) — не удалять
легаси-ветку без явного разрешения владельца.

## Регрессионный тест (обязательно)
Новый файл `tests/test_data_translations.py` (или дополнить существующий по локализации):
1. `engine.load()` на tmp-сейве С `"language": "ru"` → `ACHIEVEMENTS[0]["name"] == "Первая кровь"`.
2. `engine.load()` на tmp-сейве БЕЗ ключа `language` → имя НЕ равно `"First Blood"`
   (эффективный язык по умолчанию — ru).
3. Переключение ru → en (через `data_loader._loaded = False; load_all(); apply_translations("en");
   _wire_data()`) возвращает английский.
Смотри паттерн: тесты создают движок на tmp-пути (`GameEngine(save_path=...)`), реальный
сейв не трогают.

## Ограничения (из CLAUDE.md — обязательны)
- `# Build: N` в первой строке каждого изменённого файла — инкрементировать.
- Файлы не больше 10 КБ; конкретные `except`, без broad.
- `_wire_data` мутирует module-level коллекции IN-PLACE (`.clear()+.extend()`) — контракт
  не ломать, `ACHIEVEMENTS` не ребиндить.
- НЕ «дочинивать» имена экипировки: имена предметов остаются английскими намеренно
  (`skip=("name",)` в translationmixin — см. комментарий там), переводятся только описания.
- Перед сдачей: `python -m pytest tests -q` (сейчас 432 passed, 1 skipped — меньше быть не должно),
  плюс запуск репро-скрипта выше (оба кейса должны дать перевод).

## Не входит в задачу (часть 1)
- Реальный Android/BlueStacks-прогон (владелец проверит сам; маркер в logcat —
  `[DataLoader] Translations applied for 'ru'` после старта).
- Изменения в `data/languages/data_XX.json` для СЕКЦИИ achievements — она полная.

# Часть 2 — ДОРАБОТКА по итогам ревью (2026-07-25, вечер)

Первая реализация части 2 принята ЧАСТИЧНО. Код (`show_tutorial` + ключи `tut_*` во всех
9 языках) — принят, работает. Секции в `data_XX.json` — брак двух видов, требуется переделка.

## Брак №1: поле `desc` вместо `description` (все 8 файлов, все секции кроме lore)
Во ВСЕХ базовых данных описание лежит в поле **`description`**
(`enemies.json`, `injuries.json`, `enchantments.json`, `boss_modifiers.json`, `mutators.json`),
и UI читает `.get("description")` (проверено: enemypopupmixin.py:62, enchantmixin.py:86,
injuriesmixin.py:168). В переводах же везде записан ключ **`desc`** — merge создаёт мёртвое
поле, на экран НЕ попадает ни одно описание. Переводы имён (`name`) — рабочие.
**Фикс:** во всех 8 `data_XX.json` в секциях `enemies, injuries, enchantments,
boss_modifiers, mutators` переименовать ключ `desc` → `description` (механическая правка;
уже переведённые тексты мелких секций при этом оживут). Секция `lore` использует
правильные поля `title`/`text` — там переименований не нужно.

## Брак №2: английские копии вместо переводов
- `lore` — все 30 записей (title+text) во всех 8 языках — байт-в-байт копии английского.
- `enemies` — все 600 описаний во всех 8 языках — английские копии.
- `injuries` — все 100 описаний во всех 8 языках — английские копии.
(Мелкие секции — enchantments/boss_modifiers/mutators — переведены честно, их не трогать,
кроме переименования поля из брака №1.)
**Фикс:** реально перевести перечисленное на все 8 языков. Объём большой — делать
итеративно (по секции на язык за проход), НЕ копировать английский текст как заглушку:
ревью это ловит автоматически сравнением с базой.

## Обязательные тесты доработки (дополнить test_data_translations.py)
Рантайм-проверки (не проверки файлов!), для ru и uk минимум:
1. после `apply_translations('ru')`: `data_loader.enemies_data[0]['description']`
   содержит кириллицу; аналогично injuries, lore (title и text), mutators,
   boss_modifiers, enchantments.
2. анти-заглушка: переведённый `description` != английскому оригиналу из базового JSON
   (спот-чек по 3–5 записям на секцию).
